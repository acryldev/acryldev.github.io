01 · the loop

Write, open, point, answer.

How a review round travels

  1. 01
    Agent writes the artifact

    A plan, comparison, diagram, table, diff or interactive prototype — one self-contained HTML file.

  2. 02
    ACRYL AXI opens it locally

    The CLI starts a loopback review server and a browser surface. Nothing is uploaded.

  3. 03
    You point at what is wrong

    An element, a range of selected text, a table cell, a diagram, or a whole batch of layout findings. Each becomes one queued prompt.

  4. 04
    The agent receives it as text

    Selectors, anchors and local image paths, not screenshots. It edits the file, the page live-reloads, the round repeats.

The commands the agent runs

$npx -y acrylaxi plan.html

$npx -y acrylaxi poll plan.html

poll long-polls until you send feedback, queue layout fixes, or end the session. Requests arrive in the same turn the agent is already holding.

02 · why not screenshots

Feedback should cost tokens, not pixels.

Loop What the agent gets What it costs
Screenshots in chat An image, read back as pixels Vision tokens per round, lossy anchors
Prose description “the card in the second row” Ambiguity, re-asks, slow rounds
ACRYL AXI One prompt per note with an exact CSS selector, text range, or table cell Text only, precise, replayable
A

Local-first

Session state lives in ~/.acrylaxi/. Hosted sharing is explicit and opt-in.

B

Any agent

Claude Code, Codex, OpenCode, Copilot CLI, DSH or ACRYL. It is one CLI command.

C

Agent-authored

Design guidance, playbooks and snippets are served by the CLI itself, so they never go stale.

03 · a decision to answer here

Which capability leads the explainer?

Answer by clicking an option, then annotate anything that feels wrong. The agent reads your choice from the conversation panel — not from a screenshot of this form.

Options are local form state until you queue one answer from the panel.
