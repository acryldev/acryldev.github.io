The idea

An app is a Blend: Cordis plugins, composed, versioned, shareable

Plugins

Small Cordis plugins: a service, a tool for the agent, a UI slot. Pulled from one registry, verified by checksum.

blend.yaml + lock

Which plugins, which versions, how they are composed. Commit it, diff it, share it, restore it anywhere.

An agent inside

Every app has an agent that operates it in plain language and writes new plugins for it while it runs.

ACRYL, the agentic IDE, is the biggest Blend. A GTD planner, an accounting app and a drum machine are Blends too.

How a plugin is made

Four files, verified, installed into the running app

package.json

Name, version, what it needs and provides.

index.js

The host side: services and tools for the agent.

client.js

The UI side: fills a slot such as the header.

cordis.patch.yml

Where it sits in the app's composition.

acryl_verify_plugin checks it, acryl_install_plugin activates it without a restart, a second install updates it in place. Share it to GitHub or npm; pull anyone's with /plugin pull github:owner/repo@version, checked by sha512.

    Signal over noise

    Interoperability

    Cordis plugins run in ACRYL and in stock DeepSeek Harness; one registry lists both.

    Stability

    Every plugin is verified before it installs, pinned by version and checksum, rolled back on failure.

    Composability

    An app is a list of plugins in blend.yaml. Add, override or remove one without forking.

    Reusability

    Share a plugin or a whole app; others pull it by name instead of rebuilding it.

    Ownership

    Your app, your data, your machine. Commit your Blend to your own git.

    Open

    MIT, on GitHub and npm. acryl.dev, acrylblends.github.io, cordisplugins.github.io.
