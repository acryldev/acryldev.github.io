Agentic apps from day one

ACRYL is an agentic IDE that writes its own plugins while it runs. It is built with ACRYL Blends, an open framework where any app, from an IDE to a drum machine, is a set of plugins with an agent inside that operates it and grows it.

The mission

A new kind of software: composable software 2.0, agentic from day one

It writes itself

Ask for a feature and the agent inside builds it as a plugin, live, while you keep working.

It repairs itself

The agent tests what it built, finds what is wrong and fixes it; a broken plugin is reverted without a trace.

It adapts to its use

Two people start from the same app and end up with two different apps, each shaped by how they work.

It is made of parts

Small plugins you can add, swap, remove, version, share and reuse, so nothing is rebuilt from zero.

And it is yours: it runs on your machine, with your data, from files you can commit to your own git.

Features are no longer a moat

Fixed software ages instantly

Every user wants it slightly different; a fixed product serves the average user, and no one exactly.

What stays valuable

Software that keeps evolving with each user, with an agent inside that knows the app and grows it.

The foundation

Cordis: the plugin kernel under DeepSeek Harness and ACRYL

Cordis began as the plugin kernel of Koishi, a cross-platform chatbot framework (Discord, Telegram, Matrix and more) with more than 4,000 community plugins. It was extracted in 2022 as a meta-framework that knows nothing about LLMs, agents or tools. DeepSeek Harness forked it as @deepseek-ai/cordis and built the whole agent as Cordis plugins: model adapters, tools, sessions, sandboxes, storage and the interface. The design is described in the paper A Programming Paradigm for Spatiotemporal Composability (Peking University and DeepSeek-AI).

Why it exists: the session outlives its parts

A group chat or a coding session runs for days while its capabilities arrive, leave and get replaced. Cordis gives two guarantees so that never breaks the session.

Temporal composability

When a component leaves, everything it did to the shared environment is reverted: routes, tools, timers, subscriptions. No residue, and unrelated work survives.

Spatial composability

Components declare what they need. A consumer activates only when its requirements exist, keeps a stable resolution while running, and stops before its provider is withdrawn.

component = requirements + provisions + effects with undo

How it works

A plugin definition, mounted with ctx.plugin(), becomes a Fiber; the Fiber owns its Context, its effects and its child Fibers.

PartWhat it is
ContextThe scoped environment a plugin receives; services, events and effects live on it.
ServiceA named capability such as ctx.tools or ctx.llm, replaceable by another provider.
injectA live dependency contract: the plugin stays PENDING until every named service exists; a provider change reactivates it.
EffectsEvery registration is owned and has an inverse; unloading runs the inverses in reverse order.
FiberOne mounted plugin instance: PENDING, LOADING, ACTIVE, FAILED, UNLOADING, DISPOSED.
LoaderRows in cordis.patch.yml become the live plugin tree; change a row and the tree updates.

Context: each plugin sees the world through its own ctx; isolate gives two groups their own provider of the same service name.

Fiber lifecycle. PENDING is not an error: the plugin is mounted and waiting for what it injects.

Services and inject: consumers depend on a name; a replaced provider reactivates them.

Events: emit, parallel, serial, bail and waterfall.

Waterfall: each listener wraps the next; next() continues, returning without it answers or vetoes.

Effects: registered 1, 2, 3; reverted 3, 2, 1 when the plugin unloads.

Loader: rows of cordis.patch.yml become the live tree of Fibers.

// a Cordis plugin, simplified: needs the tools service, adds one tool
export const name = 'word-count'
export const inject = ['tools']

export function apply(ctx) {
  ctx.tools.register(defineTool({
    name: 'word_count',
    description: 'Count words in a text',
    parameters: { text: { type: 'string' } },
    async execute({ text }) { return text.split(/\s+/).filter(Boolean).length },
  }))
  // unloading the plugin unregisters the tool: no cleanup code
}

What Cordis does not do

Cordis composes a running process. It does not describe, version or share an app: a profile is a local list of bundles on one machine, nothing pins exact versions and checksums, and there is no registry of whole apps to start from. That gap is why the DeepSeek Harness community already has thousands of plugins that solve the same problems again and again.

An app in one file

kind is a Blueprint to start from, or a Blend grown from one. extends inherits another app's rows so you override only what differs. rows are Cordis plugins and their config, the same rows the Loader runs. @webboxes/blends-core validates it, and the lock pins every plugin by version and checksum.

# registry/blends/acryl.music/blend.yaml (real)
apiVersion: blends.acryl.dev/v1alpha1
kind: Blueprint
metadata:
  id: acryl.music
  name: Music
  version: 0.1.0
  category: creative
  license: MIT
  visibility: public
spec:
  runtime: cordis
  extends: acryl.blank
  rows:
    - id: brand
      name: acryl-brand
      config: { name: Music, tagline: Say the beat, hear the beat. }
    - id: acryl-music
      name: acryl-music

Why we built it: write a piece once, everyone can reuse it

Compose

An app is rows of Cordis plugins. Add, override or remove one without forking anything.

Lock

The lock pins every plugin: a local folder by content hash, npm by integrity, a pulled plugin by source and sha512.

Share

Push a plugin or a whole app to git or a registry, private or public. Others pull it by name, verified.

Reuse and grow

acryl new --from starts from anyone's app; the agent inside adds plugins; a snapshot records it all again.

ACRYL and the open framework run the same packages: @webboxes/blends-core, @webboxes/plugin-hub and @webboxes/app-persistence on npm, MIT.

The lock records where every plugin came from: a folder inside the app (by content checksum), npm, or a plugin pulled from GitHub (by source and sha512). The same lock format is written by ACRYL and by the acrylblends framework.
